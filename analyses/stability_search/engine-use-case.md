# Draft Engine use case for the owner to file

Proposed title: Prepare supplied stability trials once and batch their evaluation against reactive parents

Downstream: `tannerpolley/Amine-Thermodynamics`, issue #385; Engine reference `391dfe5d64ede5036bf160bc6ae037ad5e14af32`, wheel SHA-256 `0962e21d2fa7a8ba1ed4622f1110b3e8053bacd878fa41c999d85e8b9afab66b`.

The Part II finite search evaluates all earlier split compositions at every searched reactive parent. An AMP profile with 5,895 supplied entries took 8.606 s in supplied evaluation versus 0.289 s in native Full search on one instrumented state. The complete 52-state profile took 424.915 worker-seconds before output. Exact duplicate trials are already evaluated once in the downstream worker. Dropping other trials would change the scientific search and is not requested.

The pinned API accepts a list through `StabilityOptions.trials` and `evaluate_supplied_trials=True`. Internally, `phase_stability.cpp::run_stability` reconstructs, compiles, evaluates residuals, checks density admission, calls `phase_energy`, and computes donor diagnostics per trial. The public `Mixture.states` batch returns homogeneous properties; it cannot supply an admitted stability-trial result or preserve these diagnostics. There is no exposed prepared-trial catalog consumed by `stability_test`.

Requested capability: an Engine-owned immutable prepared catalog bound to the model, species order, trial kind, support, exact composition, packing, and temperature. Reuse pressure-independent equation-of-state work where valid; perform pressure-dependent admission at the declared pressure. Batch the catalog against multiple solved reactive parents, including native vectorized pressure admission and donor contractions rather than repeating the scalar trial driver. Keep candidate-plane correction, positive-donor checks, uncertainty, density branch, unavailable evidence and every per-trial quantity in the Engine. The returned ordering and multiplicity must remain the declared ordering and multiplicity.

Exact `(T,P)` sharing alone is insufficient: no pair repeats among the 1,844 applicable rows of AMP amended search 106; PZ has 8,852 groups for 9,080 rows; MDEA has 63,990 groups among 65,197 rows with known supplied pressure. Reuse across temperature/trial EOS work and cheaper pressure admission need investigation in the Engine. We have not established that energy caching alone meets the target: CPU sampling attributed about 12% of sampled work to the `phase_energy` stack, with incomplete stack unwinding, and homogeneous property calls are only a timing proxy.

Acceptance case: same fixed supplied list and model at AMP amended search 106 and the DEA current record. Reproduce each state's availability, descent, supplied-negative and unavailable classification, resolved density branch, and minimum TPD/RT within the existing Engine uncertainty; retain every unavailable cause. Downstream measurements currently reproduce these values exactly on stated subsets. Include representative restricted-support states from Engine #24.

Performance acceptance: a 1,906-state AMP search and 9,080-state PZ search, plus the 69,099-state MDEA search, should each take at most about 600 s on three cores, including output; report failed/unavailable counts and memory. The present downstream output changes do not achieve this. Linear projections imply approximately 8.7-fold, 41-fold and 134-fold reductions for AMP, PZ and MDEA respectively relative to the 600-second target. Native Full search, parent solves and pressure admission may still set a lower bound after prepared evaluation. Please profile those remaining terms before promising the target.

This is a draft only. No Engine issue was filed and no Engine source was edited. Engine #25's fitting memory growth is outside this request.
